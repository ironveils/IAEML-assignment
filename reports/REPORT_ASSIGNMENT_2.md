## 1. Экспериментальный сетап и RL-модель

Для обучения агента управления в среде `RobotaxiEnv` реализован алгоритм **Proximal Policy Optimization (PPO)** с обобщённой оценкой преимущества (**GAE**) на **JAX**, **Equinox** и **Optax**.

### Архитектура модели (`ActorCritic`)

* **Вход:** вектор наблюдений из `RobotaxiObservation.as_vector()`, который очищается от `NaN` и `Inf` и обрезается в диапазон `[-10.0, 10.0]` функцией `clean_obs`.
* **Скрытые слои:** два полносвязных слоя `eqx.nn.Linear` по `128` нейронов с активацией `jax.nn.tanh`.
* **Актор (политика):** выходной слой `actor_mean` выдаёт средние значения для двух непрерывных действий (`throttle_brake` и `steer_cmd`), а обучаемый параметр `actor_log_std` (ограничен в `[-2.5, 0.5]`) задаёт логарифм стандартного отклонения. Действия сэмплируются из нормального распределения и сжимаются через `tanh` в `[-1, 1]` с учётом поправки якобиана при вычислении `log_prob`.
* **Критик (функция ценности):** голова `critic_head` оценивает скалярное значение $V(s_t)$ для расчёта GAE и целевых возвратов.

### Параметры эксперимента

Финальный чекпоинт `checkpoints/ppo_robotaxi.eqx` получен на карте `map_id = 0` следующей командой:

```bash
python -m src.training.train_ppo --updates 800 --num-envs 32 --rollout-length 256 --max-steps 1000
```

Основные параметры запуска и гиперпараметры:

* **Карта и горизонт:** `map_id = 0`, `max_steps = 1000`, `discretization_scale = 1`, `path_length = 100`.
* **Сбор данных:** `num_envs = 32`, `rollout_length = 256` (`8192` шага за одно обновление, всего `6 553 600` шагов за `800` обновлений).
* **PPO и GAE:** `updates = 800`, `epochs = 4`, `minibatches = 4`, `gamma = 0.99`, `gae_lambda = 0.95`, `clip_eps = 0.2`, `vf_coef = 0.5`, `ent_coef = 0.01`, `hidden_dim = 128`, `seed = 0`.
* **Оптимизатор:** `optax.chain(optax.zero_nans(), optax.clip_by_global_norm(0.5), optax.adam(5e-4))`.

## 2. Вычислительные оптимизации

* **Параллельные среды (`jax.vmap`):** сэмплирование действий, вызов `RobotaxiEnv.step` для всех 32 окружений и перевод наблюдений в векторы выполняются батчем за один вызов.
* **JIT-компиляция цикла обучения (`@jax.jit`):** вся функция `rollout_and_update` (сбор роллаута, расчёт GAE, нормализация преимуществ и проходы градиентного обновления) скомпилирована в XLA.
* **Циклы через `jax.lax.scan`:** проход по шагам роллаута, обратный расчёт GAE (`compute_gae`) и проход по эпохам/мини-батчам реализованы через `scan`, чтобы избежать раздувания графа и долгой компиляции.
* **Автосброс внутри векторизованного шага:** при наступлении `done` отдельные среды сбрасываются в `init_state` и `init_obs_vec` через `jnp.where` без остановки остальных окружений.
* **Прямая запись видео без промежуточных PNG:** в `eval_ppo.py` при указании `--record` кадры экрана Pygame (`pygame.surfarray.array3d`) переворачиваются в `(height, width, 3)` и пишутся сразу в `.mp4` через `imageio`.

## 3. Трудности и как они решались (Рефлексия)

1. **Борьба со стратегией «газ в пол и в стену» через функцию награды:**  
   На ранних прогонах PPO часто застревал в двух крайностях: либо жал тормоз и стоял на месте (`speed = 0.000`), либо выкручивал руль и на полной скорости врезался в стену на первых сотнях шагов, потому что прогресс считался по прямой до цели без учёта маршрута и препятствий. Когда я усилила влияние продвижения вдоль спланированного маршрута (`PATH_PROGRESS_WEIGHT = 10.0` против `PROGRESS_WEIGHT = 4.0`), добавила штраф за отклонение от пути (`PATH_FOLLOW_WEIGHT = 1.0`), бонус за движение вперёд и штраф за остановку, агент перестал просто впечатываться в стену на старте и начал аккуратнее проходить повороты на `map_id = 0`.

2. **Эксперимент с `lookahead` в функции награды:**

   Я пробовала сдвигать целевую точку маршрута вперёд (`lookahead = 2` при расчёте `path_progress` в `step`), рассчитывая, что агент будет плавнее проходить повороты. На практике с разными ненулевыми значениями `lookahead` результаты были заметно хуже. На поворотах агент пытался срезать траекторию и из-за этого врезался в стены. Поэтому в `step` я оставила `lookahead = 0` (а смещение `+ 3` оставила только в наблюдении `get_observation`), и только с этим обучение сдвинулось в плюс.

3. **Долгий выход в положительную награду и подбор длины обучения:**

   На запусках с меньшим числом обновлений агент долго оставался в отрицательной награде. При прогоне на `600` обновлений (`--updates 600 --num-envs 32 --rollout-length 256 --max-steps 1000`) ближе к 375–600 апдейтам средняя награда за шаг впервые вышла в плюс (около `+0.25`), возврат за эпизод вырос до `+70..+83`, число столкновений упало до нуля, и доля успехов стала ненулевой. После этого я увеличила обучение до `800` обновлений и получила более стабильное поведение на первой карте (`map_id = 0`).


4. **Почему на второй и третьей картах поведение хуже:**

   `train_ppo.py` обучает модель только на одной карте, заданной через `--map-id` (`0` по умолчанию), сбрасывая среды в один и тот же `init_state`. В итоге на `map_id = 0` агент доезжает до цели отлично, но на `map_id = 1` он врезается, а на `map_id = 2` вообще стоит. Причина ещё и в том, что маршрут перестраивается каждые `REPLAN_EVERY_N_STEPS = 10` шагов по текущим позициям всех препятствий, включая движущиеся: когда кинематическое препятствие перекрывает проход, перестроенный путь уходит в стены, а притормозить и переждать мешает штраф за простой (`STANDSTILL_PENALTY`).

### Локальный запуск и воспроизведение

1. Активируйте виртуальное окружение:

   ```bash
   python -m venv .venv

   # Windows (PowerShell):
   .\.venv\Scripts\Activate.ps1

   # Linux / macOS:
   source .venv/bin/activate
   ```

2. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Запустите оценку обученного чекпоинта на карте `0` с записью видео в `results/ppo_eval.mp4`:

   ```bash
   python -m src.training.eval_ppo --checkpoint checkpoints/ppo_robotaxi.eqx --map-id 0 --max-steps 1000 --max-frames 600 --record results/ppo_eval.mp4
   ```

3. Чтобы посмотреть работу агента в окне Pygame без записи видео, запустите без `--record`:

   ```bash
   python -m src.training.eval_ppo --checkpoint checkpoints/ppo_robotaxi.eqx --map-id 0 --max-steps 1000
   ```

4. Чтобы воспроизвести обучение с параметрами финального чекпоинта:

   ```bash
   python -m src.training.train_ppo --updates 800 --num-envs 32 --rollout-length 256 --max-steps 1000
   ```
